      Para hablar como ingeniero
      
      Glosario del agente
      
      
      Los términos que usan los equipos que construyen agentes, con su nombre en inglés y el capítulo donde aparecen.
      
    
      
    
      
      
      Tokentoken
      Pedazo de texto: una palabra, parte de una palabra o un signo. El modelo lee el texto como tokens y escribe uno a la vez. cap. 1
      
      
      Modelo de lenguajeLLM
      Red neuronal entrenada para predecir el siguiente token. Es la parte que razona y decide; no ejecuta nada. cap. 1
      
      
      Agenteagent
      Sistema que usa un modelo dentro de un ciclo: decide un paso, lo ejecuta con herramientas, observa el resultado y repite hasta cumplir un objetivo. cap. 1
      
      
      Contextocontext
      Todo lo que el modelo recibe en una vuelta: instrucciones del sistema, herramientas, mensajes y resultados. Salvo lo aprendido al entrenarse, lo que no está ahí no existe para él. cap. 2
      
      
      Herramientatool
      Función externa que el agente puede pedir: consultar, buscar, reservar, enviar. Se describe con nombre, descripción y esquema de entrada. cap. 3
      
      
      Esquema de entradaJSON Schema
      Descripción estructurada de qué datos acepta una herramienta y de qué tipo. Le enseña al modelo a pedirla bien. cap. 3
      
      
      Llamada a herramientatool call
      Solicitud que escribe el modelo con el nombre de la herramienta y sus datos. Es solo texto; quien la ejecuta es el arnés. cap. 3
      
      
      Arnésharness
      El programa alrededor del modelo: arma el contexto, valida y ejecuta llamadas, aplica permisos y límites, y registra cada paso. cap. 3
      
      
      MCPModel Context Protocol
      Estándar abierto para conectar herramientas y fuentes de datos a los agentes, como un enchufe universal. cap. 3
      
      
      Razonamientoreasoning
      Texto que el modelo genera para pensar antes de actuar: planear, comparar opciones y corregir. cap. 4
      
      
      Observacióntool result
      Lo que devuelve una herramienta. Entra al contexto como datos para la siguiente decisión, incluidos los errores. cap. 4
      
      
      ReActreason + act
      El patrón del ciclo: pensar, actuar, observar y repetir. Casi todos los agentes actuales usan alguna versión de él. cap. 4
      
      
      Aprendizaje por refuerzoreinforcement learning
      Entrenamiento en el que las secuencias de decisiones que logran el objetivo se refuerzan y las que fallan se desalientan. cap. 5
      
      
      Ventana de contextocontext window
      Máximo de tokens que el modelo puede ver a la vez. Todo lo que el modelo lee y escribe en un paso tiene que caber ahí. cap. 7
      
      
      Compactacióncompaction
      Resumir la parte vieja del contexto para liberar espacio, procurando conservar lo importante. Normalmente el resumen lo escribe el propio modelo. cap. 7
      
      
      Humano en el ciclohuman-in-the-loop
      Pausa en la que una persona aprueba o rechaza una acción importante antes de que se ejecute. cap. 8
      
      
      Inyección de instruccionesprompt injection
      Texto malicioso escondido en datos externos que intenta darle órdenes al agente. La defensa empieza por tratarlo como datos, nunca como órdenes. cap. 8
      
      
      Subagentesubagent
      Agente al que otro agente, el orquestador, le delega una parte de la tarea. Trabaja con su propio contexto y devuelve un resultado. cap. 9
      
      
      Evaluacionesevals
      Conjuntos de tareas de prueba para medir qué tan seguido el agente termina bien y en qué falla. cap. 9
      
    
      
  
      

  
      El ejemplo es inventado para explicar la mecánica: los lugares, reseñas, horarios, tokens y probabilidades no son reales. Un modelo real elige token por token; aquí agrupamos esas probabilidades por acción para que se vean. Los JSON siguen la forma de los bloques tool_use y tool_result de la API de Claude, simplificados: sin identificadores y con el resultado como campos directos.
